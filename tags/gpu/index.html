  • 백업 GPU 자가치료 전멸과 모의계좌 체결 오매칭 원인 규명

  • 공유계좌 실거래 확장과 GPU 이중화, 그 사이 측정 도구 자체의 결함들
    이번 달은 공유계좌로 실거래 범위를 넓히고 두 번째 그래픽카드로 처리 능력을 이중화하는 진전이 있었고, 그 과정에서 벤치마크·리포트·안전장치 같은 측정 도구 자체의 결함을 반복해서 찾아 고쳤습니다
  • R9700 백업 GPU 전멸 사고, 두 번 틀린 원인 진단
    어젯밤 붙인 자가치료가 이번엔 전혀 먹히지 않았고, 빠진 종목을 되살리는 과정에서 원인 진단을 두 번이나 다시 뒤집었습니다.
  • R9700 백업 GPU 자가치료 배선과 동시요청 상향 재검토
    죽은 슬롯을 고치는 코드를 실전에 붙였고, 동시 요청을 더 늘리자는 판단이 틀린 전제 위에 있었다는 걸 확인했습니다.
  • 안전장치를 겹겹이 쌓고, 전제를 다시 검증한 한 주
    서버 퇴화 감지부터 GPU 죽은 슬롯 감지까지 안전장치를 여러 겹 쌓았고, 그 사이사이 "고친 게 정말 원했던 걸 이뤘나"를 다시 검증해 틀린 전제를 찾아냈습니다.
  • R9700 백업 GPU, 병목 원인과 죽은 슬롯 감지기
    백업 경로가 왜 동시 요청을 늘려도 안 빨라지는지 원인을 찾았고, 슬롯이 죽어서 응답이 폭주하는 문제를 잡아내는 감지기를 만들었습니다.
  • 뉴스 수집 범위 실시간화와 보조 카드 안전장치 배포
    어제 시각 조정만으로는 풀리지 않던 문제를 오늘 뉴스 수집 구조 자체를 바꿔서 풀었고, 보조 카드 상시운용을 위한 안전장치도 실제로 배포했습니다.
  • 야간 실행 시각 조정과 보조 카드 상시운용 설계 검토
    검증해보니 시각 조정만으로는 원래 목표를 이루지 못했고, 보조 카드 상시운용 자문에서는 예전에 참고했던 성능 수치가 오독이었다는 것도 확인했습니다.
