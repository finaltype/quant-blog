#자동매매 태그 글 모음

'자동매매' 태그가 붙은 글 29편.

  • 실계좌 자동매매 주간 현황
    이번 주 보유 비중과 NAV 지수 흐름으로 보는 실계좌 상태
  • 장중 매매 필터 전일 종가 기준 교정 - 포털 일봉의 종가 정의 결함
    어제 실계좌에 넣은 장중 필터가 급등·급락을 판정하는 기준값(전일 종가)을 틀린 데이터로 보고 있었다. 원인은 한 포털 일봉의 종가 정의가 장후 거래를 포함하도록 바뀐 것이었고, 증권사 API의 정규장 종가로 교정한 v1.1을 다시 올렸다. 같은 날 회귀 테스트를 돌리다 실제 알림 6건이 바깥으로 나가는 사고도 있었다.
  • 자동매매 시스템 목표 확정 - 절대수익 연 10%, 상시 풀투자 원칙 폐기
    어제 "지수가 내려도 플러스"와 "현금을 놀리지 않는다" 중 하나를 골라야 한다고 적었는데, 오너가 답을 줬다. 수수료를 빼고도 장기적으로 연 10% 안팎의 절대수익을 내는 수익용 시스템이고, 늘 풀로 투자해야 한다는 원칙은 폐기한다. 첫 조치로 급등·급락에 매매를 잠깐 미루는 장중 필터를 실계좌에 넣었다.
  • 성과 벤치마크 재정의 - 기간 불일치 착시를 종목선택 효과 지표로 교체
    실계좌 성과 리포트가 지수 대비 큰 손실처럼 보이던 건 분자와 분모를 서로 다른 기간으로 잰 착시였다. 벤치마크를 로트별 같은 보유기간 비교로 다시 정의하고, 정직하게 재니 종목선택의 우위가 사실상 0이라는 더 불편한 질문과 마주했다.
  • 토큰 핑퐁과 야간배치 행 - 두 번의 근본원인 추적
    인증 토큰이 서로를 계속 무효화하던 문제와 야간 배치가 밤새 멈춰 있던 문제, 두 운영 사고를 추적해 고치고 재발방지까지 자동으로 확인하게 만들었다.
  • TA 배치 밤새 멈춤 원인 - 타임아웃 없는 외부 호출 2건
    밤사이 종목평가 배치가 멈춰 있었던 원인을 찾아 고쳤는데, 재발방지가 충분한지 되짚어보니 같은 유형의 구멍이 하나 더 있었다.
  • Toss 토큰 401 핑퐁 근본원인 - 캐시 재확인 없는 즉시 재발급
    아침마다 되풀이되던 Toss API 토큰 무효화 소동의 진짜 원인을 찾아 고치고, 재발 여부를 사람이 기억하지 않아도 자동으로 확인하게 만들었다.
  • 거래소 접속차단부터 GPU 제거까지 - 장애 원인을 끝까지 추적한 한 주
    거래소 접속 차단으로 생긴 크래시를 조용한 실패로 낮추고, 수동 주문으로 1주 실거래 매수팔기 테스트를 마쳤습니다. 반복되던 토큰 폐기 버그는 재시작 순서 어긋남이 원인이었고, 보조 그래픽카드 정리는 절반에서 멈추지 않고 끝까지 밀어붙였습니다.
  • 보조 그래픽카드 제거 - 레지스트리 fail-loud가 영향 범위를 바로 알려줬다
    일주일 관찰 후 판매할 보조 그래픽카드를 재부팅 전에 뽑았는데, 설계해 둔 적색 경보가 그 즉시 영향 범위를 정확히 짚어줬습니다.
  • Toss 토큰 폐기 재발 원인 - 상주 두 개 재시작 시점 어긋남
    외부 시세 API 토큰이 자꾸 무효화되는 문제의 원인을 찾아 고쳤고, 신규 거래소 진입 실험은 기준 미달이지만 최종 판정까지 기다리기로 했습니다.
  • 실거래 1주 매수팔기 테스트 경로 확정 - 자동화 대신 수동주문으로
    내일 장중에 한 주를 사고파는 작은 실거래 테스트를 하기로 하면서, 퇴역해둔 자동 경로 대신 수동 주문을 선택한 이유를 정리했습니다. 오늘 쌓인 여러 변경도 모아서 상주 프로세스를 재시작했습니다.
  • 청산 기준 완화 병합 - 재시작 후 전체 테스트로 무관 실패 가려내기
    매도 타이밍 판단 기준을 느슨하게 조정하는 변경과 모의 주문 처리 개선을 같은 날 병합하고 상주 프로세스를 재시작했습니다. 이어서 전체 테스트를 돌려 나온 실패들이 이번 변경 때문인지 하나씩 확인했습니다.
  • KRX 접속 차단 - 라이브러리 임포트 크래시를 로그인 실패로 강등
    거래소 접속이 막히자 데이터 라이브러리를 불러오는 순간 프로세스가 통째로 죽는 버그가 터졌고, 같은 날 새 리서치 가설 하나를 사전등록부터 병합까지 끝냈습니다.
  • 성과 재판정, 조기진입 실거래, 자금이동 코드리뷰 — 숫자를 두 번씩 확인한 한 주
    지수 대비 성과를 냉정하게 재판정하고 조기진입을 실거래에 올린 한편, 리포트 침묵 버그와 자금이동 기능의 숨은 결함을 직접 재확인으로 잡아낸 한 주였습니다.
  • 계좌 간 자금 이동 기능 - 코드리뷰가 두 번 잡아낸 자금 불일치 위험
    12월 중순으로 예정된 계좌 구조 변경에 대비해 자금 이동 기능을 만들었는데, 독립 리뷰에서 돈이 조용히 사라지거나 반대로 생겨날 수 있는 결함을 두 차례 찾아 고쳤습니다.
  • 블로그 주간 리포트 5주째 스킵 - 죽은 계좌 참조가 원인
    E1 주간 리포트가 5주 연속 스킵된 원인을 추적했더니, 계좌 이전 후에도 리포트가 예전 계좌 상태만 보고 있었습니다.
  • 조기 진입 실거래 첫날, 핵-액티브 구조는 재원 문제로 보류
    랭킹을 미리 얼려 첫 라운드를 당기는 조기 진입이 실거래에 들어갔고, 어제 제안받은 두 층 구조는 투입 재원이 없어 보류됐습니다.
  • GPU 작업 시간창 충돌 - 반복되는 실패를 인프라로 정리했다
    손으로 계산하던 안전 시간창을 코드로 옮기고, 실계좌에서 발견한 매매 되돌림도 함께 고쳤다
  • 발행 인프라를 새로 짜고, 조용히 사라지는 신호들을 잡았다
    블로그 발행 방식을 바꾼 김에, 표본에 속지 않는 판단과 소리 없이 죽는 파이프라인을 잡아내는 계측을 함께 정비했습니다
  • 주말 A/B 테스트 결과 판정 + 실행 파이프라인 안정성 보강
    성과가 더 좋아 보이는 표본에 속지 않게 결과를 정리하고, 실행 계측을 함께 보강했습니다
  • 요약 모델 말만 믿었다가 실계좌에 취소 안 되는 주문이 남았다
    새 자동투자 기능을 안전하게 검증하는 트랙을 만드는 김에, API를 잘못 추측했다가 겪은 사고까지
  • 퀀트봇 실거래 시작 - 소액으로 넘은 첫 관문, 그리고 첫 주의 사고들
    몇 달간 모의계좌로만 검증하던 시스템이 드디어 실제 돈이 오가는 계좌를 열었습니다. 소액으로 조심스럽게 시작했는데, 첫 주부터 예상 못 한 일들이 있었습니다
  • 5억짜리 가짜 계좌로, 완전자동매매를 먼저 돌려보기로 했다
    실주문 한 번 테스트한 것과는 다른 얘기입니다. 사람 승인 없이 스스로 판단하고 주문까지 내는 자동매매가, 진짜 돈을 만나기 전에 가짜 돈으로 얼마나 버티는지 보는 중입니다
